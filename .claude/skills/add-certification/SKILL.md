# Add Certification

Registers a newly earned certification on the portfolio site by editing two source-of-truth
JSON files and, if the certification has a digital badge, regenerating the fetched badge data.

## Data model

- `src/data/certifications.json` — array of `{ category, items: [{ name, date }] }`.
  Always edit this file. Existing categories: `IPA資格`, `AWS`, `英語`, `その他`.
  - `name`: short label as shown on the site (e.g. `"SAP-C02"`, `"基本情報技術者"`, `"TOEIC 845点"`) — not the full official title.
  - `date`: `"YYYY.MM"` format.
  - Within a category, `items` are ordered ascending by date — insert the new entry at the
    correct chronological position, don't just append.
  - If no existing category fits, add a new `{ category, items: [...] }` object at the end
    of the top-level array.
- `src/data/badge-urls.json` — array of `{ source, url, note }`, only for certifications that
  have a public digital badge (Credly or NetLearning/JDLA OpenBadge). Append the new entry at
  the end.
  - `source`: `"credly"` if the URL is `credly.com/badges/{uuid}/public_url`; `"netlearning"` if
    it's an `openbadge-global.com` / `nlp.netlearning.co.jp` OpenBadge share link.
  - `url`: the public badge URL, exactly as given.
  - `note`: the full official certification/badge title, used as a fallback display name if the
    live fetch ever fails. **Don't ask the user for this** — derive it from the badge itself (see
    step 3) and normalize any en dash (`–`) in the fetched name to a plain hyphen (`-`), matching
    every existing entry in this file (e.g. `"AWS Certified Solutions Architect - Professional"`).
- `src/data/badges.json` — **never hand-edit**. It is generated by `node scripts/fetch-badges.js`,
  which reads `badge-urls.json` and fetches live badge data from Credly/NetLearning.

## Procedure

1. **Collect what can't be derived.** If the user's message doesn't already contain these, ask:
   - Short name/label as it should appear in the list (e.g. `"SAP-C02"`, `"基本情報技術者"`) —
     Credly/badge data never contains this short form, so always ask for it.
   - A public digital badge URL, if one exists (Credly `public_url` link, or a NetLearning/JDLA
     OpenBadge share link). Most certifications the user will register have one — ask explicitly
     if not mentioned. If truly none, ask for category and date obtained (`YYYY.MM`) manually and
     skip straight to step 4.

   Don't ask for category, date, official title, or issuer up front when a badge URL is available
   — step 2 derives all of it from the badge itself.

2. **If a badge URL was given, fetch its live data first — don't guess.**
   - Credly (`credly.com/badges/{uuid}/public_url`): extract the uuid and run
     `curl -s https://www.credly.com/api/v1/public_badges/{uuid}`. Read
     `data.badge_template.name` (official title), `data.issued_at_date` (`YYYY-MM-DD`, convert to
     `YYYY.MM`), and `data.issuer.entities[0].entity.name` (issuer, for your own context).
   - NetLearning/JDLA: the OpenBadge API has no single simple endpoint like Credly's; instead add
     a provisional entry to `badge-urls.json` (step 3) and run `node scripts/fetch-badges.js`
     (step 5) — its output lines (`name (issuedOn)`) give you the same official title/date. Adjust
     `note` afterward if the fetched name differs from your provisional guess.
   - Infer the category from the official title/issuer using this repo's existing convention:
     AWS-issued certs (name starts `AWS Certified ...`) → category `AWS`, using the short exam
     code (e.g. `ANS-C01`) the user gave you as `name`. Other issuers don't have a dedicated
     category yet (see `GCP CDL` filed under `その他`) — suggest a category to the user rather
     than assuming.

3. **Edit `src/data/certifications.json`.** Read the file, find or create the matching category,
   insert `{ "name": ..., "date": ... }` (date from step 2, or from the user if no badge) at the
   correct chronological position within that category's `items`. Preserve the existing 2-space
   indentation and trailing newline.

4. **If a badge was provided, edit `src/data/badge-urls.json`.** Append
   `{ "source": "credly" | "netlearning", "url": ..., "note": ... }` as the last element, using
   the official title fetched in step 2 for `note` (hyphen-normalized per the Data model section).

5. **If `badge-urls.json` was changed, regenerate badges:**
   ```
   node scripts/fetch-badges.js
   ```
   Run from the repo root. This hits the Credly/NetLearning APIs live — confirm it printed the
   new badge's name/date at the end of its output, and that the date matches what you put in
   `certifications.json`. If it fails (bad URL, network, API shape change), report the error and
   leave `badge-urls.json` as-is for the user to fix rather than guessing at a workaround.

6. **Show the user a summary** of what changed (`git diff --stat` / relevant diff hunks) for the
   edited/generated files.

7. **Do not commit automatically.** Only commit if the user explicitly asks. If they do, follow
   this repo's established pattern of separate Conventional Commits (see `git log`):
   - `chore: update badge data` for `badge-urls.json` + `badges.json`, if those changed.
   - `feat(certifications): add new certification <name> with date <date>` for `certifications.json`.
